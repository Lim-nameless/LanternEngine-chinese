## 怎么用

1. 安装 Python 3.8 或更高版本，安装时**务必勾选 Add Python to PATH**
   （[python.org](https://www.python.org/downloads/)）。
2. 把整个 `localization` 文件夹放到游戏根目录，和 `Lantern Engine.exe` 并排
   （也就是同时有 `engine\` 的那一层）。
3. 关掉启动器，双击 **`一键汉化.bat`**。

脚本会自己找启动器：先按已知文件名找，找不到就在上一级目录里挑体积最大的、超过 5 MB、且不是
`Bloodborne.exe` 的 exe。作者以后再改名也不用改脚本。

想回到英文，双击 **`还原英文.bat`**，原版一直留在 `Lantern Engine.exe.zh-CN-backup`。

| 脚本 | 作用 |
|---|---|
| `一键汉化.bat` | 汉化。自动备份 → 写入 → 真实启动一次确认不崩 |
| `还原英文.bat` | 从备份还原英文原版 |
| `自检.bat` | 只读检查：包结构、备份状态、汉化状态 |
| `预览汉化覆盖率.bat` | 演练模式，不写文件，把没译的条目导到 `_work\` |
| `重建标识符清单.bat` | 可选。重建「不能翻译的标识符」清单，需要 .NET SDK |

退出码：`0` 成功，`2` 已经是汉化状态，`3` 用降级词典完成，`1` 失败。

## 汉化原理

.NET 单文件包把程序集作为一个条目存放在
`[偏移][大小][压缩后大小][类型][名字长度][名字]` 的清单里。工具解析这份清单，把
`Lantern Engine.dll` 取出来改完，再按原偏移、原长度放回去。

程序集里有两个地方存界面文字：

**`#US` 字符串堆 —— C# 代码里的字面量。** 格式是
`[ECMA-335 压缩长度][UTF-16LE 内容][尾字节]`。这些记录靠 `ldstr` 指令里的**绝对偏移**
定位，彼此不需要相连，所以缩短是安全的，只要别让别的记录挪位。译文变短空出来的字节一律清零，
长度前缀照实写——**不会**把填充字符塞进字符串内容里。

**BAML 资源 —— XAML 里的文字。** 窗口标题、导航标签、搜索框提示编译进 `.g.resources`，
格式是 `[单字节长度][UTF-8]`，顺序读出、没有外部偏移，所以字节长度**必须**保持不变，译文短了
用空格补。

真正难的不是写中文，而是判断哪个字面量是给人看的、哪个是给机器认的。
`_tools/analyze.cs` 会顺着每个 `ldstr` 往后的 IL 指令分类：

- **show** —— 后面跟 `set_Text`、`MessageBox.Show`，这是显示文字，可以译；
- **cmp** —— 被比较、当字典键、传给 `XmlConvert.VerifyNCName`、或塞进 `HashSet`
  初始化器，这是标识符，**不能译**；
- **table** —— 紧跟 `stelem.ref`，静态字符串表。

`cmp` 这一类是重点。早先版本把所有字面量一视同仁，结果点「开始」立刻崩溃：`Patches.Discover`
拿 `"Metadata"` 这类值构造 `XName`，而 `XmlConvert.VerifyNCName` 会拒绝任何不是合法 XML 名的
字符串。另外翻译补丁名会让补丁列表从 22 个变成 36 个，因为发现的补丁要和 `Bloodborne.xml` 里的
条目**按名字**合并——名字一变就合不上。

所以有了 `unsafe-values.json`（404 条）这份「必须保留英文」的清单。少数值同时用于显示和比较，
两边一起变仍然一致，就通过 `allow` 白名单显式放行。

### 安全措施

- 文件长度全程不变，所有差异字节都落在 `#US` 记录或 BAML 块内——**写盘前**校验，不是事后。
- 每条 `#US` 改完立刻回读比对，只要有一条对不上，整次写入直接放弃，文件不动。
- 新程序集回填后重新校验清单（条目数、偏移、其它条目未被修改）。
- 写完自动启动一次，等 9 秒看是否到达主窗口，崩了会报出来。
- 首次汉化生成 `Lantern Engine.exe.zh-CN-backup`，之后永不覆盖。

## 哪些地方是有意保留英文的

| 保留内容 | 原因 |
|---|---|
| `Lantern Engine`（产品名） | 参与进程名和 Discord 状态判断；只有窗口标题通过 BAML 层译成了「灯笼引擎」 |
| 15 个内置补丁名 | 要和 `Bloodborne.xml` 里的补丁**按名字**合并，译了补丁列表会重复成两倍 |
| 奖杯等级 `Platinum` / `Gold` / `Silver` / `Bronze` | 来自游戏本体的奖杯 XML |
| `FSR 4`、`DLSS`、`TAA`、`RCAS`、`PSSR` | 厂商技术名 |
| 手柄型号 | 由 SDL 上报，不该自己编 |
| `Left Alt`、`Mouse2`、`Space` 等 | 是 `bbport.ini` 里真实存储的值，译了存档里的按键绑定就读不回来 |
| `Frame stats:`、`Stall:`、`THD:` 等 | 用来解析引擎的英文日志输出 |

剩下约 261 条没译的，基本是资源键、画刷与样式名、Steam VDF 键、正则、单位和语言自称。

## 怎么补翻译

本目录下任何 `zh-CN*.json` 都会被自动合并；`_` 开头的键当作注释，不参与替换。

```json
{
  "_备注": "随便写",
  "Some new label": "某个新标签"
}
```

想知道还差哪些，跑一次 `预览汉化覆盖率.bat`，看 `_work\<启动器名>-todo.json`，
每条都有 `"zh": ""` 等着填。

两条长度限制，超了会明确报错而不是悄悄截断：

- `#US` 记录可以随便变短，中文几乎不会超；
- BAML 字符串上限是原始**字节数**（一个汉字 UTF-8 占 3 字节），所以中文只能比英文短，不能更长。

启动器更新后某个页面失效，通常是新增了字面量或 BAML 块位置移动了。新字面量会被
`预览汉化覆盖率.bat` 列出来；BAML 块是按资源名表动态定位的，位置怎么挪都不影响。

## 不包含的东西

- **不含游戏文件。** Lantern Engine 需要你自己的、已解密的 Bloodborne 本体（CUSA03173）+ 1.09 更新。
  本仓库只有汉化脚本。
- **不含 Python 运行时。** 原来那个便携版有 23 MB 二进制，不该进代码仓库，请自行安装 Python。
